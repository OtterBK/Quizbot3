# 수동 테스트 체크리스트

> `develop-claude`에서 누적된 전체 구조 리팩터 + TS 마이그레이션 + 웹 연동 + 관리자 패널 등
> 신규 기능에 대한 라이브 테스트용 체크리스트 — `develop` 브랜치로 실서버에 설치해 전수 테스트할
> 때 사용. 하나씩 체크하면서 진행. 실제 대결(2개 이상 길드가 동시에 참여하는 멀티플레이 게임
> 진행)만 별도(섹션 K)로 분리 — 나머지는 혼자 테스트 가능.
>
> 문제를 발견하면 재현 조건 → 실제 동작 → 기대 동작 형태로 기록해두면 나중에 고칠 때 편함
> (`docs/archive/BUGS_FOUND.md`는 리팩터 시절 기록으로, 계속 쓰는 문서는 아님 — 새로 발견한 버그는
> `docs/ACTIVE_PLAN.md`나 새 이슈로 남길 것).

> **2026-08-15 구조 정리**: 섹션이 A→Z→AA→AE까지 기능 추가/수정 시점 순서로 계속 누적돼서(30개),
> 같은 주제(다크모드 토글/세션 GC 만료/하이재킹 방어/서버 설정)를 테스트하는 항목이 여러 섹션에
> 흩어져 찾기 어려워졌다는 문제가 발견됨. **알파벳 순서/섹션 내용 자체는 유지**하되(각 섹션이 서로
> 다른 시점에 구현된 서로 다른 세부 시스템을 검증하는 경우가 많아 물리적으로 합치면 오히려 무엇을
> 검증하는지 불명확해짐 — 예: O섹션의 세션 만료는 "퀴즈 선택" guild 세션, T섹션의 세션 만료는
> "퀴즈 만들기" owner 세션으로 서로 다른 시스템), 아래 조치만 적용:
> 1. 바로 아래 **목차**에 기능 영역별 그룹을 추가(물리적 위치는 안 바꾸고 찾기만 쉽게)
> 2. 이미 다른 섹션으로 완전히 대체돼 죽은 항목(AC섹션의 취소선 항목) 삭제
> 3. 다른 섹션과 글자 그대로 100% 중복인 항목(W섹션의 투트랙 라벨 확인) 삭제, 원본 섹션으로 위임
> 4. 같은 화면(`ServerSettingUI`)을 테스트하는 AB섹션의 서버 설정 항목 2개를 F섹션으로 합침
> 5. "왜 비슷한 걸 여러 번 확인하냐" 헷갈리는 지점(GC 만료/하이재킹 방어)에 "이건 다른 시스템"이라는
>    설명 주석 추가
