[실행 방식 - 항상 bash로 실행할 것 (2026-08-19)]

auto_script/ 밑의 모든 .sh 스크립트는 `bash script.sh`로 실행하는 걸 전제로 작성돼 있음(셔뱅도
`#!/bin/bash`). `sh script.sh`로 직접 실행하면 Ubuntu의 `/bin/sh`(dash)가 셔뱅을 무시하고 그 셸로
해석하는데, dash는 POSIX 전용이라 bash 배열 등 bash 전용 문법에서 곧바로 syntax error가 남
(실사용 중 quizbot_update.sh에서 발견 - 이전엔 `sh`로 실행하는 관례였다가 이 사고를 계기로 `bash`로
통일함). 아래 모든 실행 예시는 이미 `bash` 기준으로 적어뒀음.

[systemd 서비스(quizbot3) 동작 방식 - 2026-08-15 정리]

quizbot3.service는 Type=simple이라 systemd가 ExecStart로 띄운 node dist/index.js 프로세스 하나를
"본체"로 추적한다.
- start: ExecStartPre(잔여 프로세스 청소, 아래 참고) → ExecStart(node dist/index.js 실행)
- stop: 본체가 속한 cgroup 전체에 SIGTERM → TimeoutStopSec(20초, 기본 90초에서 단축) 안에 안 죽으면
  SIGKILL → ExecStopPost(잔여 프로세스 청소)
- restart: stop 전체 과정 후 곧바로 start 전체 과정

quizbot_stop.sh 실행 후에도 ffmpeg/yt-dlp 같은 자식 프로세스가 간혹 안 죽는 문제(cgroup kill을
빠져나가는 경우가 있는 듯) 때문에, ExecStartPre/ExecStopPost 둘 다
auto_script/server_script/kill_orphan_quizbot.sh를 실행해서 남은 node/ffmpeg/yt-dlp 프로세스를
pkill -9로 확실히 정리한다. 이 훅은 서비스 유닛 자체에 박혀있어서 quizbot_start.sh/quizbot_stop.sh
같은 래퍼 스크립트를 거치지 않고 systemctl start/stop/restart quizbot3를 직접 쳐도 항상 같이
실행된다 - start 쪽 청소가 있어서, 이전 인스턴스가 완전히 안 죽은 채 새 start가 들어와도 중복 실행
없이 항상 깨끗한 상태에서 시작한다.

**주의**: 이 훅들은 auto_script/systemd/quizbot3.service.template에 있고, install_quizbot3.sh가 설치
시점에 한 번 /etc/systemd/system/quizbot3.service로 복사해서 생성한다. quizbot_update.sh(코드
업데이트)는 이 서비스 파일을 다시 생성하지 않으므로, 2026-08-15 이전에 이미 설치된 서버에 이 개선을
적용하려면 서비스 파일을 수동으로 다시 설치해야 한다:
  sudo sh -c "sed 's|__QUIZBOT_PATH__|$QUIZBOT_PATH|g' '$QUIZBOT_PATH/auto_script/systemd/quizbot3.service.template' > /etc/systemd/system/quizbot3.service"
  sudo systemctl daemon-reload

[한글 파일명이 `ls`에 물음표로 깨져 보일 때 - 2026-08-15 이전에 이미 설치된 서버]

UTF-8 locale 설정도 install_quizbot3.sh에만 있어서 기존 서버엔 소급 적용 안 됨 - 아래를 한 번만

터미널 표시 문제였음.

  fetch/reset/npm install/npm run build를 전부 sudo(root)로 실행하면서 이후 소유권 복원 단계가 없어서,

[DB 백업 구글드라이브 오프사이트 업로드 설정 - 2026-09-03 추가]

backup_script.sh는 로컬 백업(db_backup/, 7일 지나면 자동 삭제) 외에 rclone이 설치+설정돼 있으면
구글드라이브(gdrive:quizbot_backup/)에도 같은 파일을 업로드한다. 원래 로컬 장비(개인 PC)로 주기적으로
백업을 내려받아 보관하던 걸 보완하는 용도라, 드라이브 쪽엔 **최신 백업 1개만** 남기고(업로드 성공
직후 그 폴더의 다른 파일은 전부 삭제) 여러 세대를 쌓아두지 않는다. rclone이 없거나 설정이 안 돼있으면
경고만 찍고 로컬 백업은 그대로 정상 진행 - 필수 아님.

이 스크립트는 cron에서 `sudo -E bash backup_script.sh`로 실행되므로(위 4번 참고) 결국 root 권한으로
돌아간다. 따라서 rclone 설정도 반드시 **root**로 해야 한다(사용자 계정으로 설정하면 rclone.conf가
~ubuntu/.config/rclone/에 생겨서 root가 못 찾음).

최초 1회 설정 (서버에서):
  1. rclone 설치: curl https://rclone.org/install.sh | sudo bash
  2. sudo rclone config 실행 → n(새 원격) → name: gdrive → Storage: drive(Google Drive) 검색해서 선택
     → client_id/secret은 빈 칸(엔터, rclone 기본값 사용) → scope는 2(drive.file, rclone이 직접 만든
     파일만 건드림 - 전체 드라이브 접근보다 안전) → root_folder_id 빈 칸 → service_account 빈 칸 →
     고급 설정(Edit advanced config)? n
  3. "Use auto config?"에서 서버는 브라우저가 없으므로 **n** 선택 → 안내되는 대로 로컬(브라우저 있는)
     PC에서 `rclone authorize "drive"` 실행 → 뜨는 브라우저에서 구글 로그인/권한 승인 → 터미널에 출력된
     토큰 블록을 복사해서 서버 쪽 프롬프트에 붙여넣기
  4. 원격 이름(gdrive) 확인 후 q로 종료
  5. sudo rclone mkdir gdrive:quizbot_backup 로 업로드 폴더 미리 생성
  6. sudo rclone ls gdrive:quizbot_backup 로 접근 확인 (또는 백업 스크립트 한 번 수동 실행해서 확인)
